## What this cut actually is

The async lane is in the pack: compute fills the buffer off-thread,
`take` packs the Dictionary on the main thread. Uncapped Fibonacci 13
was a regression on this machine (headed endgame 51 → 23 fps). The
shipped default bounds async packets by **worker latency × biome count**
(`ASYNC_PACKET_LATENCY_BUDGET_MS = 50`). At the endgame six-biome
ceiling that is about **3 steps/packet**.

Title and fresh still lock 60. Endgame is still a **hitch**, not a
slowdown (median faster than one vsync; the mean is the tail).

### How to read that table

- Title and fresh are the same game they were yesterday. The async lane
  does not touch them.
- **13-step packets are the worst case on this GPU.** `take()` of a
  6×13 dim-64 packet plus a 266 ms worker is a 170 ms process hitch.
  Do not restore uncapped Fibonacci.
- **1-step and 5-step async sit in the old 47–51 fps band.** They do
  not beat the 2026-08-15 tail. The remaining hitch is not “Eigen on
  the frame.” It is `take()` / whatever still shares that frame
  (physics rest, plot grid, Godot). About one >100 ms frame per packet
  on the shipped cut (111 packets, 128 frames >100 ms).
- 41 fps on the final 0af388b2 run is a **hot-machine** number after
  many back-to-back exports and endgame loads. The quiet 1-step and
  12-step runs (49–51) are the better estimate of a cold boot. Either
  way p95 is 84–121 ms. A2 wants < 33.

## Packet-size law (measured, then coded)

```
sync:   stall budget 25 ms  →  1 step at endgame
async:  latency budget 50 ms × (ms per biome-step × biomes)
        first packet 1; endgame six-biome ceiling ≈ 1–3 steps
```

The first async cut forgot to multiply by biome count, so Fibonacci 13
still shipped and headed endgame fell over. `0af388b2` has the multiply.
`native_async_lane_smoke` pins it.

## Vsync hunt (same day, restaged again)

The leftover is **not a FIFO hitch-train**. Same 30 s window:

| | capped FIFO | uncapped | mailbox (do not ship) |
|---|---|---|---|
| fps / p50 / p95 / worst | 43.9 / 11.2 / 112 / 147 | 98.1 / 4.3 / 70 / 157 | 26.3 / 17.3 / 147 / 184 |
| frames >33 / >50 / >100 ms | **152 / 151 / 102** | **152 / 151 / 66** | 177 / 137 / 130 |
| vsync_mode | 1 ENABLED | 0 | 3 MAILBOX |

Five spikes a second exist with vsync off. FIFO only changes the
percentile (fewer total frames → the same 151 slow frames become p95).
Mailbox on this 960M made present slower; reverted to ENABLED.

On a hitch frame the named ledger is ~8–15 ms (farm physics rest ~8,
field3d <1, take 0.05). The other ~90 ms is uninstrumented engine/GPU.
`TIME_PROCESS` is still sticky — do not quote it as the stall.

The buffer now keeps the flat packet (`adopt_flat_from_result`) so merge
is a move, not an Array-of-Array unpack. Hitch count did not move. That
rules out post-take GC of per-step Packed slices as the 5 Hz event.

Until A2 (p95 < 33 ms, worst < 80 ms, 1% low ≥ 20 fps at 1280×720),
do not say 60 fps about late game.
