# 🧠🗺️ Codex‑Mini Rig Plan (QA Focus)

This plan exists to **help QA playtesters complete the game loop** and surface bugs/perf issues. It is not just a description—use it to **decide new turns** and **evaluate results**.

Goal: Provide a turn-by-turn rig that lets lightweight Codex-mini instances interact with the live Farm/QuantumInstrument simulation, cycle through quests/vocab, and log each "turn" for inspection.

## Core pieces (all in 🍄/🎛️)
1. **Live rig listener** - `Rig/rig_listener.gd` keeps a single game session alive and executes JSON turns from `user://rig/queue.jsonl`, writing JSON results to `user://rig/results.jsonl`.
   - `offer_quests` now returns `type`, `completion_action`, and `reward_resources`.
2. **Rig scripts** - `🍄/🎛️/🟢.sh` starts the listener; `🍄/🎛️/✍️.sh` appends one JSON turn.
3. **SnapshotService helper** - already created, exposes overlay toggles, resource queries, quest info. This becomes the back-end control surface for the rig (accept quests, open quest board, read resources, trigger overlays, etc.).
4. **Tokenized script tooling** - `lib_qii.sh` and token logs can serve as the rig's turn history; extend them to record outcomes (success/failure) and turn IDs.
5. **Documentation/README** - explain how to spin up the rig, what scripts exist, how to interpret token/result logs, and how to add new turns.

## New quest systems (must be reflected in bot behavior)
- Rewards are resource-first and faction-shaped (`reward_resources`) plus vocab.
- Turn-in is action-specific:
  - delivery (`type == 0`) -> `complete_quest`
  - non-delivery (`type != 0`) -> `complete_or_claim`
- North vocab should be new; south vocab may repeat.
- QA proof requires both vocab and resource delta checks (`known_icons`, `resource_snapshot`).

## Phases (what to build next)
- **Phase 1 (Live rig actions).** Extend `Rig/rig_listener.gd` with more actions (quest accept/turn‑in, vocab placement, build/harvest).
- **Phase 2 (Feedback instrumentation).** Expand SnapshotService to emit per‑action outcomes (resource deltas, quest acceptance status) so the rig can close the loop.
- **Phase 3 (Docs & usage).** Keep the README focused on live‑rig usage and how Codex‑mini should actually play.

## Risks/gaps (QA‑relevant)
- Need to decide how Codex-minis specify actions: via text file, token log, or RPC? The rig should standardize a compact command set (e.g., `QII +vocab → Village`), ideally reusing the `VOCAB_QII.tsv` vocabulary.
- Some actions currently fail (missing resources, terminals). The rig should include setup turns (seed resources, bind terminals) before measurement actions.
- The sender and listener must point at the same `user://rig` root. If you run the listener with a custom `XDG_ROOT` or `GODOT_USER_DIR`, the turn writer has to use the same path or the queue will silently go to the wrong session.
